# The Bash guard

`hooks/guard-bash.py` runs before every Bash tool call in Claude Code. It reads the command and never runs it. It denies:

- `git push` to `main` or `master` (including `--all`, `--mirror`, `:` and glob refspecs). Push a branch and open a PR. GitHub wiki remotes are allowed.
- AI attribution in commit messages, PR titles and PR bodies, such as `Co-Authored-By: Claude` or "Generated with Claude Code".
- Broad process kills. Stop your own pid instead.
  - `pkill`, or `pgrep -f` fed into `kill`.
  - `killall` with a dev-server name (`node`, `ruby`, `puma`, `vite`, `rails`, `bundle`, `sidekiq`, `esbuild`, `foreman`, `overmind`, `bin/dev`, `dev-instance`) or with `-m`.
- In a repo that has linked worktrees: `git fetch` or `git pull` with `--depth`, `--deepen`, `--shallow-*` or `--unshallow`, and any `git stash` except `list` and `show`. Both change history or state that the worktrees share.
- In repos whose `.orchestration.toml` or `.orchestration.local.toml` sets `guard.big_repo = true`: every `git grep`, even with a path, and bulk `git cat-file --batch`, `--batch-check` or `--batch-all-objects` reads. The installed session instructions say to use directory-scoped `rg`, and `git show <ref>:<path>` for another ref.
- A raw Codex start that bypasses hook trust or widens the sandbox. Denied: `herdr agent start … --kind codex` with `--dangerously-bypass-hook-trust`, `-p`/`--profile`, `-a`/`--ask-for-approval`, `-s`/`--sandbox`, `--add-dir`, `--yolo`, `--full-auto`, `--approve-for-me`, `-c`/`--config` keys starting `sandbox`, `approval`, `permissions`, `profiles` or `hooks` (padding and quotes ignored), `--disable hooks`, a `$` or backtick in the agent arguments, or `--dangerously-bypass-approvals-and-sandbox`; `~/.claude/coordinator/codex-start.sh` is the way to start a bypassed worker. A plain Codex start stays allowed.
- Known limits of the Codex rules: only `herdr agent start … --kind codex` is checked. `herdr pane run` or `send-text` with `codex …` and a direct `codex --yolo` are not; the allow rule naming only `codex-start.sh` is the boundary, and auto mode still reviews raw launches.
- pi outside the start step, because a pi start with no provider uses pi's own default and DeepSeek is off unless the repo opted in. Denied: `herdr agent start … --kind pi` (the kind is trimmed and compared in lowercase; a `$` expansion in the kind value is denied too); any `herdr agent start` of any kind that names DeepSeek in its `--kind` or in the agent arguments after `--` (an agent name or a `--cd` path that contains the word is fine); `herdr pane run` and `herdr pane send-text` whose text runs a `pi` command or starts with `/model`, `/models`, `/scoped-models` or `/settings` (the text goes through the full guard, so `bash -c`, `timeout`, `nice -n` and a typed herdr pi start are covered, and so is prose that a shell would run as `pi`, such as `Review it; pi is fast`; send prose with `herdr agent prompt`); `herdr agent prompt` text that starts with `/model`, `/models`, `/scoped-models` or `/settings` (a live pi never changes model); and any `pi` run that names DeepSeek or that names neither `--provider` nor `--model`. `pi --list-models <provider>`, `--help` and `--version` are allowed only as the first argument (after `--` or as an option value the same words are prompt text), and so is a `pi` run with a provider or model on another provider. The skill always uses `~/.claude/coordinator/pi-start.sh`, which runs herdr outside the Bash tool and passes `--models` with the one model, so Ctrl+P has nothing to cycle to. The pi rules also look inside `bash -c`, `sh -c`, `zsh -c`, `eval` and double-quoted or unquoted `$(…)` and backtick bodies; the same text in single quotes is plain text.
- Known limits of the pi rules: this is a tripwire, not a sandbox. Still open: `npx` or `node <path>` running pi, `mise exec -- pi`, `xargs pi --provider <local> --model <id>` with more args read from a file, a provider spliced from shell variables (`${P}seek`, `$'\x64…'`), a custom `models.json` provider that points at DeepSeek's API under another name (the start step cannot see it), a pi extension that switches model, an exported `ORCH_PI_WORKER_MODEL` that names a non-DeepSeek provider routed to DeepSeek, letters typed with `herdr pane send-keys` or `herdr agent send-keys` (for example `p i Enter`), a fake `herdr` first on `PATH` or in an exported `ORCH_HERDR_BIN` in front of `pi-start.sh` (the script calls `$ORCH_HERDR_BIN` by absolute path when it is set, and an exported value wins over the config file), the `/scoped-models` and `/settings` selectors reached by key presses instead of a prompt, and a project-local pi extension (the start step refuses `-e` and `-a`). A model id that `pi --list-models <provider>` does not show leaves the `--models` scope empty, and then Ctrl+P can cycle every available model (read from pi's code, not run); take ids from that list.

> ⚠️ **Fail-open:** if the guard itself breaks, it lets the command through and logs the error to `~/.claude/hooks/guard-bash.log`. After linking, the installer checks that the guard denies a forbidden command.
