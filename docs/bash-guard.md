# The Bash guard

`hooks/guard-bash.py` runs before every Bash tool call in Claude Code. It reads the command and never runs it. It denies:

- `git push` to `main` or `master` (including `--all`, `--mirror`, `:` and glob refspecs). Push a branch and open a PR. GitHub wiki remotes are allowed.
- AI attribution in commit messages, PR titles and PR bodies, such as `Co-Authored-By: Claude` or "Generated with Claude Code".
- Broad process kills. Stop your own pid instead.
  - `pkill`, or `pgrep -f` fed into `kill`.
  - `kill` with `-1` as a pid operand (`kill -TERM -1`, `kill -9 -1`, `kill -s TERM -1`, `kill -- -1`), which signals every process you own. `kill -1 1234`, where `-1` is the signal, is allowed. Other negative pids (`kill -TERM -1234`) and `kill 0` are not denied.
  - `killall` with a dev-server name (`node`, `ruby`, `puma`, `vite`, `rails`, `bundle`, `sidekiq`, `esbuild`, `foreman`, `overmind`, `bin/dev`, `dev-instance`) or with `-m`.
  - The same kill rules run on code that a shell runs: `bash -c`, `sh -c` and `eval` text; a heredoc, here-string, `< file` or pipe (`echo … | sh`, `cat f | bash`) fed to a shell; and a script file. Script files are `bash`, `sh`, `zsh`, `dash`, `ksh`, `source` or `.` with a file operand (a relative name is a path), and a direct run such as `./x.sh` or `/abs/x.sh` when the file has no shebang or its shebang names one of those shells. A script that the same command writes with a heredoc, `echo`, `printf` or `tee` and then runs is scanned too (the text is read as the shell writes it: `echo -e` escapes, the `printf` format filled in with its arguments (an append or `cat` pairs the readings of its texts slot by slot; a width pads by at most one character, and only when it is wider than the text; the `0` flag and numeric precision are not applied; each reading of the text is scanned as code of its own with independent visited-file tracking and a shared byte/time budget, one fixed slot each: as written; a bash-like reading (`echo` escapes when its last `e`/`E` flag is `e`, or the `printf` format filled in with `\"`, `\'` and `\?` read); a zsh-like reading (`echo` escapes, or the `printf` format with `\"`, `\'` and `\?` kept); and the text with nothing read (`echo`), or with each argument on its own line when a `printf` conversion is not modelled; and a macOS `sh` reading (`echo` prints its option words as text and reads escapes, and the `printf` format with `\"`, `\'` and `\?` read). An additional `printf` slot scans arguments joined by spaces when any conversion is not modelled (including an unrecognized `%` sequence), else the text as written. The readings are best-effort: they cover the common bash, zsh and `sh` readings, not every option of every shell (no `echo` reads `\"`, `\'` or `\?`). A text that does not parse falls back to a word check that ignores quote characters and backslashes; alternative readings and truncation status are stored separately from source text, preserving literal bytes in script filenames), and for `tee`, `cat`, `source` and `.` the operands after `--`, `-` or the first non-option word), with the target resolved against the working directory and plain-literal variables (`S=/p; bash $S/x.sh`, `$HOME`, `~`, `$PWD`, which follows `cd` and wins over the hook's own `PWD`, and any variable the hook itself inherits, such as `$TMPDIR`). `>>`, `&>>` and `tee -a` add to the earlier text of the file (written by the same command, else on disk); `>` replaces it. Scripts and inline text that those run are followed three levels deep. A file is read only when it is a regular text file, up to 64 KB, and at most 64 `<<` of any scanned code (inline text, stdin and files) are scanned. `ksh 'text'` is also scanned as inline text, because ksh93 runs an operand it cannot open as `-c` text. A body that does not parse is checked for `pkill` and `killall` words, and the rest of the command is still checked. Writing a file that only mentions `pkill` is allowed.
  - Limits of the script scan: a `$(…)` body that sits in an assignment is followed (`x=$(bash k.sh)`), one inside a quoted word is not (`echo "$(bash k.sh)"`); `pushd` does not change the tracked directory; `cd $VAR` and `cd` into a folder the same command creates do not change it either, so a script written there and run by a relative name is missed; a variable that is assigned with `$(…)` or is not in the command or hook environment is not expanded, including output assigned by `printf -v x …` and later run with `eval "$x"`; a script copied or generated at run time (`cp`, `cat a > b`, `tee` or `tee -a` from a pipe, `tee` in the middle of a pipe) is not seen; symlinks are not resolved; the file is read when the guard runs, not when the shell runs it. `source lib.sh` is denied when `lib.sh` contains a kill in a function it only defines. `bash -n x.sh` and `bash -s x.sh` do not run the file and are not scanned. A script the command writes and then runs from a nested `bash -c 'bash k.sh'` is not seen, because each nesting level starts with no written files. The heredoc reader drops the rest of the marker line (`bash <<'EOF'; pkill -f vite`, `cat <<'EOF' | bash`, and the common `cat <<'EOF' > repro.sh`, which hides the write), as it does for every other rule.
  - Scan size: 64 KB is the limit per file. `cat a b | bash` reads the next file only while the text so far is under 64 KB, so a first file of 64 KB or more ends the join with no mark and the files after it are not scanned. A text over 64 KB that a shell runs is denied as too large to check: `printf` output piped to the shell or written to a file the same command runs (the reason names printf, as long as the text is not joined to other text), and any append or `cat` that passes 64 KB, including one of a cut `printf` text, a file on disk that the command appends to, and `cat` of files that together pass 64 KB (the reason names script text), and the same output written to a file that is not run, or piped to a command that is not a shell, is allowed; a whole hook call scans at most 512 KB of code, starts no new code after 5 seconds (the body being parsed is not interrupted), ends the scan of a body at the first `<<` followed by more than 256 word characters, and it scans each file once per nesting level and folder (a helper run again from another folder is scanned again). When either budget runs out with shell code left unchecked, the command is denied and one `guard-bash scan-budget` line goes to the log. An error inside the script scan is logged as `guard-bash scan-error`; that scan stops and every other rule still applies.
- In a repo that has linked worktrees: `git fetch` or `git pull` with `--depth`, `--deepen`, `--shallow-*` or `--unshallow`, and any `git stash` except `list` and `show`. Both change history or state that the worktrees share.
- In repos whose `.orchestration.toml` or `.orchestration.local.toml` sets `guard.big_repo = true`: every `git grep`, even with a path, and bulk `git cat-file --batch`, `--batch-check` or `--batch-all-objects` reads. The installed session instructions say to use directory-scoped `rg`, and `git show <ref>:<path>` for another ref.
- A raw Codex start that bypasses hook trust or widens the sandbox. Denied: `herdr agent start … --kind codex` with `--dangerously-bypass-hook-trust`, `-p`/`--profile`, `-a`/`--ask-for-approval`, `-s`/`--sandbox`, `--add-dir`, `--yolo`, `--full-auto`, `--approve-for-me`, `-c`/`--config` keys starting `sandbox`, `approval`, `permissions`, `profiles` or `hooks` (padding and quotes ignored), `--disable hooks`, a `$` or backtick in the agent arguments, or `--dangerously-bypass-approvals-and-sandbox`; `~/.claude/coordinator/codex-start.sh` is the way to start a bypassed worker. A plain Codex start stays allowed.
- Known limits of the Codex rules: only `herdr agent start … --kind codex` is checked. `herdr pane run` or `send-text` with `codex …` and a direct `codex --yolo` are not; the allow rule naming only `codex-start.sh` is the boundary, and auto mode still reviews raw launches.
- pi outside the start step, because a pi start with no provider uses pi's own default and DeepSeek is off unless the repo opted in. Denied: `herdr agent start … --kind pi` (the kind is trimmed and compared in lowercase; a `$` expansion in the kind value is denied too); any `herdr agent start` of any kind that names DeepSeek in its `--kind` or in the agent arguments after `--` (an agent name or a `--cd` path that contains the word is fine); `herdr pane run` and `herdr pane send-text` whose text runs a `pi` command or starts with `/model`, `/models`, `/scoped-models` or `/settings` (the text goes through the full guard, so `bash -c`, `timeout`, `nice -n` and a typed herdr pi start are covered, and so is prose that a shell would run as `pi`, such as `Review it; pi is fast`; send prose with `herdr agent prompt`); `herdr agent prompt` text that starts with `/model`, `/models`, `/scoped-models` or `/settings` (a live pi never changes model); and any `pi` run that names DeepSeek or that names neither `--provider` nor `--model`. `pi --list-models <provider>`, `--help` and `--version` are allowed only as the first argument (after `--` or as an option value the same words are prompt text), and so is a `pi` run with a provider or model on another provider. The skill always uses `~/.claude/coordinator/pi-start.sh <name> <pane> <worker|smart|provider/model-id>` (a model id must be one entry of `ORCH_PI_MODELS`), which runs herdr outside the Bash tool and passes `--models` with the one model, so Ctrl+P has nothing to cycle to. The pi rules also look inside `bash -c`, `sh -c`, `zsh -c`, `eval` and double-quoted or unquoted `$(…)` and backtick bodies; the same text in single quotes is plain text. In `herdr pane run` or `send-text` text that starts with `$(…)` or a backtick, every reading of an `echo` or `printf` body is checked (as written, with escapes read, with the `printf` arguments filled in); a `printf` body whose output passes 64 KB is denied as too large to check. `command -v pi` only looks the name up, so it is allowed when the whole command is plain lookups with `echo`, `true`, `false`, `exit` and `if`, and redirects only to `/dev/null` or `>&1`/`>&2`; `command pi` runs it and stays denied.
- Known limits of the pi rules: this is a tripwire, not a sandbox. Still open: text built by `printf` or `echo` outside that one form (a top-level `"$(printf '%s' pi)"`, `bash -c "$(printf …)"`, `eval "$(printf …)"`, pane text where the `$(…)` does not start the text such as `"cd /x; $(printf '%s' pi)"`, unquoted `$(…)` pane text, a `$(…)` nested inside the body, or a `printf` format in inner double quotes that holds a `;`), `npx` or `node <path>` running pi, `mise exec -- pi`, `xargs pi --provider <local> --model <id>` with more args read from a file, a provider spliced from shell variables (`${P}seek`, `$'\x64…'`), a custom `models.json` provider that points at DeepSeek's API under another name (the start step cannot see it), a pi extension that switches model, an exported `ORCH_PI_WORKER_MODEL` that names a non-DeepSeek provider routed to DeepSeek, letters typed with `herdr pane send-keys` or `herdr agent send-keys` (for example `p i Enter`), a fake `herdr` first on `PATH` or in an exported `ORCH_HERDR_BIN` in front of `pi-start.sh` (the script calls `$ORCH_HERDR_BIN` by absolute path when it is set, and an exported value wins over the config file), the `/scoped-models` and `/settings` selectors reached by key presses instead of a prompt, and a project-local pi extension (the start step refuses `-e` and `-a`). A model id that `pi --list-models <provider>` does not show leaves the `--models` scope empty, and then Ctrl+P can cycle every available model (read from pi's code, not run); take ids from that list. A zsh global alias in a pane's rc turns a plain word into shell text, and the guard cannot see that.

> ⚠️ **Fail-open:** if the guard itself breaks, it lets the command through and logs the error to `~/.claude/hooks/guard-bash.log`. After linking, the installer checks that the guard denies a forbidden command.
