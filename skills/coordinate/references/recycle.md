# Required command walkthroughs

Read this file before the action named by its SKILL.md link. All source command requirements and caveats below remain in force.

- **Architect recycle.** `RECYCLE-WORKER` goes to the owning architect; do not act on it. On `RECYCLE`: send the architect the handover order (finish the current call, overwrite (never append) `handoff_<initiative>.md` in memory, under about 4,000 characters, using the fixed template in `~/.claude/skills/architect/SKILL.md`, reply with the path, stop). When the path arrives: open a new pane in the same workspace, `herdr agent start <name> --kind claude --pane <pane> -- --model $ORCH_ARCHITECT_MODEL --name "<architect name>" --remote-control "<architect name>"`, use the Claude-only Recycle-start exception in SKILL.md’s Messages rule to probe it with `date` and prompt "`/architect` … read `<handoff file>` first, then resume; the Coordinator is `<your session name>`", have the successor read only the handoff, not the old transcript, and take over workers by pane id, copy the `owner` and `role` tags, wait for its first status line, Verify `~/.claude/sessions/<pid>.json` has a non-null `bridgeSessionId` after the start. Then close the old pane with `~/.claude/coordinator/watchers/close-pane.sh <old pane id>`, which marks it as closed on purpose and removes the mark when the close fails. **Names stay the same across a recycle:** the successor's Claude session name (`--name <same>`), its Herdr agent name and its tab name are those of the ancestor, so `ListAgents`, the Radar tree and the user see one continuous architect. One architect at a time; never one that holds a heavy slot mid-run.

- **Coordinator recycle.** At the threshold of your own context: overwrite (never append) `handoff_coordinator.md`, under about 4,000 characters, using this fixed template: (per-architect picture, standing decisions with dates, open questions and open question panes, running Monitors and their scripts, the memory files a successor reads first), open a new tab in your workspace named `Coordinator`, start the successor there with `herdr agent start coordinator --kind claude --pane <pane> -- --model $ORCH_COORDINATOR_MODEL --name Coordinator --remote-control "Coordinator"` (the Herdr agent name is free once the ancestor's agent is released; if it is still taken, start as `coordinator-next` and the successor renames itself and its tab to `Coordinator` before it closes the ancestor), use the Claude-only Recycle-start exception in SKILL.md’s Messages rule to probe it with `date` and prompt "`/coordinate` — read `handoff_coordinator.md` first, then notify architects through the native channel that you are the Coordinator now", have it read only the handoff, not the old transcript, verify its `~/.claude/sessions/<pid>.json` has a non-null `bridgeSessionId`, tag its pane `role=coordinator`, stop your own Monitors, including the feed Monitor, so they do not fire twice, and tell the user in one line which pane to use from now on. **The successor closes its ancestor:** it stops any Monitor it inherited, arms the one feed Monitor (`~/.claude/coordinator/watchers/feed-monitor.sh`), and runs `python3 ~/.claude/coordinator/watchers/bind-self.py --output ~/.claude/coordinator/watchers/bindings/coordinator.json` as one Bash call on its own (never chained with `&&`, `;` or a pipe; `install.sh` installs the allow rule for exactly this command, so it runs it itself). If auto mode still blocks it, tell the user once. Once the architects have acknowledged, it closes the ancestor's pane with `~/.claude/coordinator/watchers/close-pane.sh <ancestor pane>` and, if that was the tab's only pane, the tab. The ancestor never closes itself.
