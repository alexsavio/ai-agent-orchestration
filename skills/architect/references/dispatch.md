# Required command walkthroughs

Read this file before the action named by its SKILL.md link. All source command requirements and caveats below remain in force.

The shape for a delegated task:

1. **A worktree per task, anchored to your own workspace** — `herdr worktree open --workspace "$HERDR_WORKSPACE_ID" --path <existing worktree> --label <short-name> --no-focus`, or `herdr worktree create --workspace "$HERDR_WORKSPACE_ID" --branch <name> --base <ref>` when it does not exist yet. **Always pass `--workspace`.** Left out, Herdr picks the parent itself and can nest your workers under an unrelated project, so the user sees their initiative filed under someone else's. One workspace per task keeps branches and panes aligned.
   **Before opening, check the path is not already open** — `worktree open` on an already-open path silently **renames** the existing workspace instead of creating a new one. A reviewer always gets its own detached worktree at a different path, never the author's.
2. **An agent in its root pane, with the model chosen explicitly** — `herdr agent start <name> --kind claude|codex --pane <pane-id> -- --model <model>`. Native agent arguments go after `--`. **Never let the model default**: a pane starts on whatever the agent's own default is, which may happen to match your intent but was not a decision. State the tier in the dispatch note so the choice is reviewable. Names are `[a-z][a-z0-9_-]{0,31}` and unique among live agents. To check live names, panes, status and owners run `orch-agents` (one line per agent); never read the raw `herdr agent list` JSON (about 10k tokens).
3. **Legacy check (repos whose repo settings turn `legacy.scan` on).** Before the worker writes code, verify the source clone's origin identifies the task repository and generate a fresh task map before every check with `ORCH_LEGACY_MAP_OUT` (never reuse the daily map). Send the Coordinator the 3-line `LEGACY CHECK` from SKILL.md with the repo, source clone, map path and successful generation result and wait for `LEGACY OK`. Tell the worker to hold code until you pass it on.
4. **An allowed worker brief as a prompt** — `herdr agent prompt <name> "<handoff>" --wait --timeout 120000`. Use this only for a new worker’s first brief or follow-ups to an owned worker pane nobody types into, as required by SKILL.md’s Messages rule. A `timeout` error from the wait does not mean the prompt failed; check `herdr agent get <name>` before resending, or you will double-prompt.
5. **Name the report path in the brief.** End every hand-off with: *write your complete report as Markdown to `<scratchpad>/<issue>-report.md` and reply with only that path.* An agent renders on the alternate screen, so its reply is not recoverable from scrollback — asking afterwards costs an extra round trip per task. Naming the path upfront also keeps the report out of your context until you choose to read it, which matters because your session is the long-lived one.
6. **Read progress** across your workers with `orch-agents` (one line per agent), and one agent with `herdr agent get <name>` (status only, cheap) and `herdr agent read <name> --source recent-unwrapped --lines 120`. Read the report file when the agent is `done`, and read the part you need rather than the whole file.


**Re-home a Claude worker on the same model without losing its context** by resuming its session from the same cwd: read `agent_session.value` from `herdr agent get <name>`, `herdr worktree open --path <its worktree>` (the new pane is `.result.root_pane.pane_id`), stop the old agent (`/exit` may stop on a "running shell tasks" confirmation, so the name stays taken until that is cleared), then `herdr agent start <name> --kind claude --pane <pane> -- --model <model> --resume <session-id>`. Never re-home a worker that holds the heavy-job slot; wait until it releases it.


For a model or tier change, do not resume the old session on a different model. Follow SKILL.md’s Model changes rule: write a bounded handoff and start a fresh successor on the new model.
